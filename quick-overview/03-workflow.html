01 Prerequisites

What you need before starting

🤖 A coding agent CLI

Install at least one: claude (Claude Code), codex, cursor-agent, or gemini. OD auto-detects whatever is on $PATH.

🔑 An API key

For your agent CLI (e.g. ANTHROPIC_API_KEY) or use BYOK mode. Daemon never holds credentials — they stay in your environment.

⚙️ Node.js + npm/pnpm

Node 18+. No Docker, no database, no accounts. Everything runs locally with a single npm install.

02 Setup

Three commands to start

# 1. Clone and install
git clone https://github.com/nexu-io/open-design
cd open-design
npm install

# 2. Start daemon (:7456) + Vite web UI (:5173)
npm run dev:all

# 3. Open
open http://localhost:5173

All npm scripts

CommandWhat it does
npm run dev:allStarts daemon + Vite together — the primary dev command
npm run daemonJust the daemon (no web UI)

Production mode: npm run start serves the built SPA from the daemon itself at http://localhost:7456. One process, one port, no proxy involved.

Three controls are pre-selected in the top bar. You can change all three at any time — the next send uses the new combination immediately:

ControlDefaultWhat it changes

Type any prompt describing what you want and hit Send. The 4-stage loop begins immediately.

04 The loop

The 4-stage design loop

Every generation flows through this sequence, enforced by the discovery prompt rules. The stages are not skippable — they exist to prevent the agent from improvising bad aesthetics.

1

Detect → Agent & context loaded

Daemon scans $PATH for 12 coding agents. Auto-loads 31 skills + 72 design systems on boot. Selects best available agent. Zero config needed.

2

Discover → Brief locked in 30 seconds

Turn 1 is always a question form — never code, never file reads. Questions: output type (deck/prototype/dashboard/…), platform surface, who the audience is, what visual tone (up to 2 choices), and optionally a brand reference URL or screenshot. Answering takes 30 seconds. Skipping causes 30 minutes of redirect loops.

3

Direct → Visual direction chosen

If you said "pick a direction for me", a second form presents 5 curated visual directions. Each has a specific OKLch palette, font pairing, spacing rhythm, and layout posture cue. You pick one. The agent is now locked to that aesthetic — no improvising.

4

Deliver → Artifact generated + previewed

TodoWrite plan streams live. Agent pre-reads skill reference files (enforced). Writes to disk. 5-dimensional self-critique runs. <artifact> emitted. Preview loads in sandboxed iframe. Click "Save to disk" to persist under ./.od/artifacts/.

What "deliver" looks like in real time

  • A live TodoWrite list streams in the chat pane — you see exactly what the agent is planning
  • The artifact tree populates with file names as they're created on disk
  • The preview iframe hot-reloads as index.html is written, debounced at 100ms
  • When the agent finishes, the 5-dim critique gate runs silently — low scores trigger revision
  • The final preview loads with comment mode and sliders now active
05 Modes

Four design modes

Each mode maps to a distinct skill type and a distinct workflow shape. The mode picker in the top bar routes you to the correct skill set and enables the right export options.

ModeWhat you getTime to first resultPrimary export
PrototypeSingle editable screen (HTML/JSX)60–120sHTML, PDF, ZIP
DeckMulti-slide HTML presentation90–180sHTML, PPTX, PDF
TemplatePopulated copy of a curated template20–40sHTML, ZIP
Design SystemA DESIGN.md + sample component preview60–180sDESIGN.md

Mode: Prototype

One high-fidelity interactive screen. The UX flow: skill picker → optional structured inputs form → free-text prompt → generate → preview with comment mode and sliders → export. Default skills: saas-landing, dashboard, pricing-page, docs-page, blog-post, mobile-app.

Mode: Deck

Multi-slide magazine-quality presentation. Same flow as prototype but the skill picker shows only deck skills, the preview renders with arrow-key/scrollwheel navigation, and export adds PPTX as a first-class option. Deck skills emit a slides.json intermediate for PPTX generation. Default skill: guizang-ppt (fork of the viral op7418/guizang-ppt-skill).

Mode: Template

The fast path. Agent copies assets/template/ to the artifact dir and personalizes content — no design decisions made from scratch. Much faster than prototype mode (20–40s), higher quality floor, lower ceiling. Best for: known layout patterns you use repeatedly.

Mode: Design System

Generates a DESIGN.md from a text brief, screenshot, or reference URL. After the run, OD prompts you to set this DESIGN.md as the project's active design system — it becomes the visual context for all future generations. This is the highest-leverage thing you can do for output consistency.

06 Comment mode

Comment mode — surgical edits

Comment mode activates once the preview loads and is available when the active agent has surgicalEdit capability (currently: Claude Code, and constrained versions for other agents).

1

Click an element in the preview

The web app captures the [data-od-id] attribute from the sandboxed iframe DOM on the element you clicked.

2

Write your note in the popover

E.g. "Make this headline 20% larger", "Change this button to an outline style", "Replace this image with a data chart".

3

Daemon sends surgical edit request

Sends { artifactId, elementId, note } to the agent. The agent receives the original file + element ID + your note.

4

Agent applies targeted edit

Claude Code uses its native tool loop to edit only that region. Other adapters get a constrained re-generation: "only change element X". Preview hot-reloads when the file write lands.

Capability gating: If the active agent lacks surgicalEdit capability, comment mode is disabled in the UI for that session. Switch to Claude Code to enable it.
07 Iteration

Iteration patterns

Three ways to refine an artifact after first generation:

💬 Chat refinement

Free-text in the chat pane: "Move the CTA above the fold", "Add a pricing comparison table", "Make the hero section full-screen". Full regeneration with the new instruction added to context.

💡 Comment mode

Click a specific element. Write a targeted note. Only that element is modified — much faster than full regeneration for small changes. Requires surgicalEdit capability.

🎛️ Sliders

If the skill declares od.parameters (e.g. accent_hue, section_spacing), live slider controls appear. Moving a slider re-sends only the changed parameter — instant aesthetic tweaks with no round-trip.

Iteration strategy guide

  • Use chat for structural changes: layout shifts, new sections, content rewrites
  • Use comment mode for component-level changes: button styles, typography, color tweaks on specific elements
  • Use sliders for global aesthetic parameters: overall accent hue, spacing density, font scale
  • Use skill swap to try the same brief in a completely different surface type
  • Use design system swap to try the same brief in a different brand language
08 Customization

Customizing the workflow

Every layer of the system is a file you can edit or replace. Here are the main customization paths:

Write a custom skill

Drop a folder in ./skills/ with a SKILL.md. The daemon hot-reloads it — no restart needed in dev mode.

# Minimum structure
./skills/
└── my-skill/
    ├── SKILL.md           # frontmatter + workflow instructions (required)
    ├── assets/            # template files the agent writes from
    └── references/        # knowledge docs the agent reads first
        ├── checklist.md   # quality checklist enforced by skill
        └── components.md  # component library reference

Create a brand design system

# Create DESIGN.md in your project root
touch ./DESIGN.md
# Daemon finds it automatically — overrides all 72 built-in systems

Use a different AI provider (BYOK)

Switch the mode picker to "Anthropic API · BYOK" and paste a baseUrl + API key for any OpenAI-compatible provider:

DeepSeek

Paste DeepSeek baseUrl + API key. Full tool use supported.

Groq

Paste Groq baseUrl + API key. Fast inference for prototyping.

OpenRouter

Single key, access to many models. Route to any supported model.

Self-hosted vLLM

Paste your local http://localhost:8000 baseUrl. Fully air-gapped.

09 Export

Export your artifact

When generation finishes, the Export menu in the top-right becomes available. The artifact is always already on disk at ./.od/artifacts/<slug>/ — export formats are generated on-demand from that source.

FormatBest forNotes
HTML (self-contained)Sharing, embedding, deployingAll CSS inlined, assets as data: URIs. Single file, works fully offline.
ZIPFull project handoffComplete folder including all assets. Open index.html in any browser.
PDFPrint, email, formal deliveryPuppeteer renders the HTML. Full CSS + web font support. (Phase 2)
PPTXDeck presentations, PowerPoint usersVia pptxgenjs from slides.json. Deck mode only. (Phase 2)
MarkdownDocumentation, editorial contentAvailable for skills that output .md as primary artifact.

Working with artifacts outside OD

  • Every artifact folder is self-contained — open index.html in any browser without running OD
  • Commit ./.od/artifacts/ to git to track design history like code — review in PRs
  • Deploy the HTML file to any CDN or static host directly
  • The artifact.json records the exact skill, design system, prompt hash, and parent artifact for full reproducibility
10 Best practices

Best practices for quality output

  • Create a project DESIGN.md first. Run the Design System mode with your brand brief before any prototype generation. This single action has the highest impact on output quality and consistency.
  • Pair skill + design system intentionally. dashboard + Linear is very different from dashboard + Stripe. Spend time exploring pairings.
  • Answer the discovery form fully. The 30-second brief locks in parameters that prevent the agent from making arbitrary aesthetic decisions. Don't skip it.
  • Use comment mode for small changes. Full regeneration for layout shifts; comment mode for component-level tweaks. Much faster iteration.
  • Write skills for repeated patterns. If you produce the same type of UI repeatedly, write a SKILL.md for it with your quality checklist. Every future generation follows it exactly.
  • Commit ./.od/ to git. Design history is as valuable as code history. Review design decisions in pull requests just like code changes.
  • Target the 5-dim critique. If output feels generic, look at which dimension is failing: Is it Philosophy (no point of view)? Specificity (generic copy)? Restraint (too much going on)?
