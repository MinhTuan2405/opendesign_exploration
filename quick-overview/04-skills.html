01 Concept

What is a skill?

A Skill is the atomic unit of design capability in OD. It is a directory containing a SKILL.md file (plus optional assets and reference docs) that instructs the agent on how to produce a specific type of design artifact.

Skills define: the workflow to follow, the quality checklist to enforce, what reference files to read before generating, what the primary output file should be named, and optionally OD-specific UI extensions like typed input forms and live sliders.

Compatibility guarantee: A skill written for plain Claude Code runs in OD without modification. A skill that doesn't use OD extensions (od: frontmatter) runs equally well in plain Claude Code. The OD extensions are purely additive — they unlock UI features without breaking anything.
02 Base format

Base skill structure (Claude Code compatible)

# Directory layout — minimum required
<skill-root>/
├── SKILL.md              # manifest + workflow instructions (required)
├── assets/               # templates and boilerplate the agent writes from
│   ├── template.html     # seed file the agent copies and fills
│   └── ...
└── references/           # knowledge docs the agent reads at turn 3
    ├── components.md     # component library reference
    ├── layouts.md        # layout patterns reference
    └── checklist.md      # quality checklist the agent runs before emitting

SKILL.md frontmatter (base)

---
name: my-skill-name
description: |
  One paragraph describing what this skill does.
  Include trigger keywords so the agent can auto-select it.
  Trigger keywords: landing page, marketing, SaaS homepage
triggers:
  - "landing page"
  - "marketing page"
  - "SaaS homepage"
---

# Body: free-form Markdown workflow instructions

## Step 1: Read reference files first (always)
Before generating anything, read:
- references/checklist.md
- references/layouts.md

## Step 2: Clarify brief
Ask user for product name, key value propositions, and CTA text.

## Step 3: Generate
Write index.html following the active design system tokens exactly.
Do not invent colors or fonts not in the DESIGN.md.

## Self-check (before emitting artifact)
Score output on: Philosophy, Hierarchy, Execution, Specificity, Restraint.
Revise if any dimension scores below 7/10.
03 OD extensions

OD-specific extensions (all optional)

Skills can declare an od: block in frontmatter to unlock OD-specific UI features. All fields are optional — absent fields fall back to sensible defaults.

---
name: magazine-web-ppt
description: Magazine-style horizontal-swipe web deck.
triggers: ["magazine deck", "杂志风 PPT", "horizontal swipe presentation"]

# ── OD Extensions (all optional) ────────────────────────
od:
  mode: deck              # prototype | deck | template | design-system
  
  preview:
    type: html            # html | jsx | pptx | markdown
    entry: index.html     # which file the iframe loads
    reload: debounce-100  # how the preview refreshes

  design_system:
    requires: true        # inject active DESIGN.md into prompt
    sections: [color, typography]  # token pruning — save tokens

  inputs:               # renders a typed form in sidebar instead of free-text
    - {name: title, type: string, required: true}
    - {name: slide_count, type: integer, default: 8, min: 4, max: 20}
    - {name: theme, type: enum, values: [editorial, minimal, brutalist]}

  parameters:           # live sliders that re-prompt on change post-generation
    - {name: accent_hue, type: hue, default: 18, range: [0, 360]}
    - {name: section_spacing, type: spacing, default: 48, range: [16, 128]}

  outputs:
    primary: index.html   # file the iframe loads
    secondary: [slides.json]  # files read by export pipeline (e.g. PPTX)

  capabilities_required:
    - surgical_edit       # disables comment mode if agent lacks this
    - file_write
---

Extension field reference

FieldUsed byEffect when set
od.modeMode/skill pickerRoutes skill to the correct mode tab
od.preview.typePreview rendererPicks iframe render strategy: HTML raw, JSX eval, PPTX viewer, Markdown
od.preview.entryPreview iframeWhich file loads when generation completes
od.design_system.requiresPrompt builderWhether to inject active DESIGN.md into system prompt
od.design_system.sectionsToken optimizerPrunes injected DESIGN.md to listed sections only — saves tokens
od.inputsSidebar UIRenders a typed form (string / integer / enum / boolean) instead of free-text
od.parametersSlider overlayLive-tweakable controls after first generation; re-prompts without full round-trip
od.outputs.primaryPreview + exportWhich file the iframe loads and HTML export inlines
od.outputs.secondaryExport pipelineFiles read by export pipeline (e.g. slides.json for PPTX)
od.capabilities_requiredCapability gatingDisables comment mode or sliders if active agent lacks the capability

Defaults when od: is omitted

FieldDefault
modeInferred from name/description keyword match, else "prototype"
preview.typeSniffed: *.html → html, *.jsx → jsx, else markdown
preview.entryFirst file matching the sniffed type
design_system.requirestrue if body mentions "design system" or "DESIGN.md"
inputs, parametersNone (free-text prompt only)
04 Discovery

Skill discovery and priority

The daemon scans 3 locations on boot and on file-system watch events. All locations are merged with higher priority winning on name conflicts.

LocationPriorityPurposeGit
./.claude/skills/1 HighestProject-private skills — not sharedGitignored
./skills/2 MediumProject-committed skills — shared with teamCommitted
~/.claude/skills/3 LowestUser-global skills — available in all projectsn/a

All locations are watched with chokidar in dev — add a skill folder and it appears in the UI immediately, no restart needed. In production, send SIGHUP to the daemon to trigger a rescan.

Symlink strategy: Maintain a central skill dir at ~/.open-design/skills/ and symlink it into each agent's expected location (~/.claude/skills/, ~/.codex/skills/, etc.). One install → every agent sees every skill.

06 Skill types

Skill types — technical deep dive

prototype-skill

prototype
Primary output: index.html or Prototype.jsx
Preview: HTML iframe or JSX with vendored React/Babel
Typical workflow: clarify brief → resolve design tokens from DESIGN.md → write component tree → write file → run self-check
Export: HTML, PDF, ZIP

deck-skill

deck
Primary output: index.html (single-file deck with in-page navigation)
Secondary output: slides.json (for PPTX export)
Preview: Full iframe with arrow-key/scrollwheel/touch navigation
Typical workflow: clarify topic + slide count → pick theme → populate slides from layout catalog → self-check quality rubric
Export: HTML, PPTX, PDF

template-skill

template
Purpose: Start from a pre-built artifact. Agent personalizes content, doesn't design from scratch.
Typical workflow: copy assets/template/ to artifact dir → replace content placeholders → optionally tweak tokens to match DESIGN.md
Speed: 20–40s (no design decisions = much faster)
Quality: Higher floor than prototype, lower ceiling — the template constrains the output

design-system-skill

design-system
Primary output: DESIGN.md
Preview: Markdown render with a sample-components preview
Input options: text brief, screenshot (vision), reference URL
Post-run: OD prompts user to set this DESIGN.md as the project's active design system — it becomes the visual context for all future generations
07 Writing skills

Writing a custom skill — complete guide

Step 1: Create the directory

mkdir -p ./skills/my-landing/references
mkdir -p ./skills/my-landing/assets

Step 2: Write SKILL.md

---
name: my-landing
description: |
  Custom landing page skill for B2B SaaS products.
  Optimized for developer audiences with code examples.
  Trigger keywords: developer landing, API docs page, B2B SaaS

od:
  mode: prototype
  preview:
    type: html
    entry: index.html
  design_system:
    requires: true
    sections: [color, typography, components]
  inputs:
    - {name: product_name, type: string, required: true}
    - {name: has_code_example, type: boolean, default: true}
    - {name: cta_text, type: string, default: "Start for free"}
---

## Pre-flight (always do this first)
Read references/checklist.md, references/layouts.md before writing any code.

## Step 1: Clarify brief
Extract from user prompt: product name, key differentiator, target persona.

## Step 2: Structure
Follow the hero → social proof → features → code demo → pricing → CTA flow
from references/layouts.md. Don't invent sections.

## Step 3: Visual tokens
Use ONLY the colors and fonts from the active DESIGN.md.
Never add your own colors. Never change font families.

## Step 4: Code example section
If has_code_example is true, include a syntax-highlighted code block
showing the simplest possible API call.

## Self-check before emitting artifact
Run references/checklist.md. All items must pass.
Score Philosophy, Hierarchy, Execution, Specificity, Restraint.
Revise if any dimension below 7/10.

Step 3: Write the checklist

# references/checklist.md

## P0 — Must pass before emitting
- [ ] All colors from DESIGN.md only
- [ ] All fonts from DESIGN.md only
- [ ] No placeholder copy — all text is specific to the product
- [ ] CTA button is visible above the fold
- [ ] Mobile responsive (tested at 390px)

## P1 — Should pass
- [ ] Logo placeholder in header
- [ ] At least 3 feature items
- [ ] Social proof section present

Step 4: The skill appears automatically

Save the files. The daemon's chokidar watch picks it up — the skill appears in the dropdown immediately in dev mode. No restart needed.

Skills with side files: If your skill has assets/ or references/ files, they get an automatic "Skill root (absolute)" preamble in the prompt so the agent can resolve paths correctly against the real on-disk location.
08 Compatibility

Compatibility with Claude Code skills

OD adopts Claude Code's SKILL.md convention verbatim as the base format. This means:

  • Any existing Claude Code skill drops into ~/.claude/skills/ and OD discovers it automatically
  • OD skills without the od: extension block run unchanged in plain Claude Code
  • Community skills from the Claude Code ecosystem work in OD immediately
  • The guizang-ppt-skill from GitHub is bundled verbatim — no modifications, original LICENSE preserved
