02 API

Daemon REST + SSE API

The daemon exposes REST endpoints under /api/* on port 7456. The primary real-time communication is over SSE (Server-Sent Events) or WebSocket.

REST endpoints

MethodPathDescription
GET/api/agentsList all detected agent CLIs with capability info
GET/api/skillsList all available skills with frontmatter metadata
GET/api/skills/:nameGet full SKILL.md body for a specific skill
GET/api/design-systemsList all available design systems
GET/api/design-systems/:nameGet full DESIGN.md body for a specific system
GET/api/artifactsList all artifacts in the current project
GET/api/artifacts/:idGet artifact metadata and file list
POST/api/artifacts/saveExplicitly persist an artifact to disk (usually auto)
POST/api/uploadUpload an image or file for use in generation

Session WebSocket messages

MethodDirectionPayload
session.generateClient → Daemon{ sessionId, prompt, modeHint }
session.refineClient → Daemon{ sessionId, artifactId, elementId, note }
session.cancelClient → Daemon{ sessionId }
event.tool_callDaemon → Client{ type, name, input } — agent tool invocation
event.text_deltaDaemon → Client{ text } — streaming agent text
event.thinkingDaemon → Client{ thinking } — agent reasoning block (if supported)
event.artifactDaemon → Client{ artifactId, primaryFile, filesWritten } — generation complete
event.errorDaemon → Client{ message, recoverable }
03 CLI

Daemon CLI commands

# Start daemon in foreground
od daemon

# Start daemon and expose via cloudflared tunnel (Topology B)
od daemon --expose

# Trigger skill rescan (production — no FS-watch)
kill -HUP $(pgrep -f "od daemon")

# List all detected agents
od agents

# List all available skills
od skills

# Test a specific skill (Phase 2)
od skill test <skill-name> --prompt "test prompt"

# Validate a DESIGN.md
od design-system validate ./DESIGN.md
04 Config

Configuration options

.od/config.json

{
  "daemon": {
    "port": 7456,
    "artfactsDir": "./.od/artifacts",   // override artifact location
    "skillsDirs": ["./skills"],          // additional skill dirs to scan
    "designSystemPath": "./DESIGN.md"    // override design system location
  },
  "agent": {
    "preferred": "claude",               // force a specific agent instead of auto-detect
    "timeout": 120000                    // agent timeout in ms (default 120s)
  },
  "defaults": {
    "skill": "web-prototype",           // default skill on first load
    "designSystem": "neutral-modern"    // default system on first load
  }
}

07 Roadmap

Official roadmap

Phase 0 — Spec finalization Complete

All interfaces specified before implementation. JSON schemas for frontmatter, DESIGN.md format, HTTP/SSE API, and adapter interface. Working example skill and DESIGN.md written.

Phase 1 — MVP In progress ~6–8 weeks

  • Next.js 16 web app: chat pane, artifact tree, sandboxed preview, export menu
  • Local daemon: HTTP/SSE API, skill registry, artifact store, design-system resolver
  • Agent adapters: Claude Code (native) + API fallback
  • Export: HTML + ZIP only
  • Skills: saas-landing + magazine-web-ppt
  • Topologies: A (fully local) + C (Vercel + direct API)
  • Explicitly out: Codex/Cursor/Gemini adapters, comment mode, sliders, PDF/PPTX export

Phase 2 — Beta ~4–6 weeks post-MVP

  • Agent adapters: Codex, Cursor Agent, Gemini CLI
  • Comment mode + surgical edits
  • Live parameter sliders
  • PDF + PPTX export pipeline (Puppeteer + pptxgenjs)
  • Template gallery + template skill mode
  • Topology B: Vercel + tunneled local daemon
  • Design System skill: from screenshot / PDF / URL (vision input)
  • Docker compose file for self-hosted teams

Phase 3 — v1 Public

  • Skill testing framework: od skill test
  • Multi-user / auth layer for team deployments
  • Remaining adapters: Devin, Hermes, Pi, Kimi, Kiro, Qwen, Copilot
  • Full desktop app shell (Topology A native binary)
  • Skill registry / marketplace
Estimate basis: All phase estimates assume one focused developer. Multiply by 0.6 for two developers and 0.4 for three.
08 Glossary

Glossary

TermDefinition
ArtifactThe output of a generation — a folder under ./.od/artifacts/ containing index.html, artifact.json metadata, and optional assets.
DaemonThe long-running Node.js process that bridges the web UI to agent CLIs. Runs on port 7456. Owns session state, skill registry, artifact store, and export pipeline.
SkillA directory containing a SKILL.md that defines the workflow and output contract for a specific type of design artifact.
Design SystemA DESIGN.md file following the 9-section schema. Defines visual identity: palette (OKLch), fonts, spacing, components, motion, voice.
AdapterThe code layer that wraps a specific coding agent CLI (Claude Code, Codex, etc.). Implements: detect → spawn → stream → report capabilities.
Discovery promptThe src/prompts/discovery.ts layer that enforces the 3 hard rules: turn 1 is always a question form, turn 2 is direction picker or brand extraction, turn 3+ is generation.
BYOKBring Your Own Key — OD supports any OpenAI-compatible provider. Daemon never stores credentials.
Surgical editA targeted refinement that modifies only a specific DOM element (identified by [data-od-id]) without regenerating the full artifact.
OKLchA perceptually uniform color space. OD uses it for all color tokens because equal lightness steps look equal to the human eye, unlike hex values.
5-dim critiqueThe self-evaluation gate run before every artifact emission: Philosophy · Hierarchy · Execution · Specificity · Restraint. Low scores trigger revision.
SessionPer-tab ephemeral state in the daemon: active agent, skill, artifact, design-system body cache, in-flight tool calls. GC'd after 24h. Separate from artifacts (which are permanent).
Token pruningThe od.design_system.sections frontmatter field that limits DESIGN.md injection to only the sections a skill actually uses — saves tokens, reduces noise.
