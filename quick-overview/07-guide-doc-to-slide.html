⚡ Practical Guide 01 — OpenCode CLI

Document → Presentation Slide

Turn any document — research paper, report, or thesis chapter — into a polished deck for your class and supervisor, using OpenCode CLI as the design engine. Step-by-step from a blank screen to a presentation-ready file.

Steps
What you will produce Before you start 1. Launch Open Design 2. Set OpenCode as agent 3. Prepare your document 4. Pick skill & design system 5. Write your prompt 6. Answer discovery form 7. Pick visual direction 8. Watch generation 9. Review & refine 10. Export
Reference
Time estimate Troubleshooting
0 Overview

What you will produce

By the end of this guide you will have a complete, presentation-ready slide deck that you generated from your document using Open Design and OpenCode. The whole process takes about 25–35 minutes from document to finished deck.

End result

  • A multi-slide horizontal-swipe HTML deck — opens in any browser, no software needed
  • Magazine-quality editorial layout from the guizang-ppt skill
  • Visual identity matched to a professional design system you choose
  • Exportable as HTML (for live presentation), PDF (for submission), or PPTX (for PowerPoint)
  • All files saved locally under .od/artifacts/ — nothing sent to the cloud
💡
This guide assumes Open Design is installed from source and starts without errors. If you just finished the install and haven't tested it yet, run corepack pnpm run dev:all first and confirm the browser opens at http://localhost:5173 before proceeding.
0 Before you start

Pre-flight checklist

Everything you need ready before Step 1

Open Design installed. Running corepack pnpm run dev:all from D:\WorkSpace\HIPTECH\open_design\open-design starts without errors.
OpenCode CLI installed. Verify with opencode --version in PowerShell — should print a version number.
API key available. OpenCode needs ANTHROPIC_API_KEY (or whichever provider it's configured for). Confirm it's set in your environment.
Your document content prepared as plain text or Markdown (see Step 3 below for the exact format).
30–40 minutes of uninterrupted time. The daemon must stay running throughout.

Install or verify OpenCode

# Check if OpenCode is already installed
opencode --version

# If "not recognized", install it:
npm install -g @opencode-ai/opencode

# Set your API key for this PowerShell session:
$env:ANTHROPIC_API_KEY = "sk-ant-your-key-here"

# To make it permanent (persists after reboot):
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", "sk-ant-...", "User")

Launch Open Design

Start the daemon and web UI — takes about 10 seconds

Open PowerShell, navigate to your Open Design folder, and start everything:

# Navigate to your install
cd D:\WorkSpace\HIPTECH\open_design\open-design

# Start daemon + web UI
corepack pnpm run dev:all

Wait for output similar to this before doing anything else:

  VITE ready in 312ms

  od daemon listening on http://localhost:7456

The line "Detected agent: opencode" confirms the daemon found OpenCode on your PATH. If you see "No agents detected" instead, check the troubleshooting section at the bottom of this page before continuing.

Now open your browser and go to http://localhost:5173. Keep the PowerShell window open and running in the background — do not close it at any point during this guide.

2

Set OpenCode as the active agent

Confirm the right agent is selected in the top bar

In the top bar of the Open Design UI, find the Agent dropdown (leftmost control). Click it and confirm OpenCode is selected. Since the daemon detected it on startup it may already be pre-selected.

OpenCode capabilities — what's available in your session
Multi-turn conversations
✅ Full support
File write / read
✅ Full support — writes to your artifact folder
Comment mode (surgical edit)
⚠️ Constrained — works, edits a slightly larger region
Native SKILL.md loading
⚠️ Partial — skill is injected via the system prompt
Live parameter sliders
⚠️ Depends on skill version — may not appear
⚠️
OpenCode's constrained surgical edit means comment mode works, but when you click an element and leave a note, OpenCode may regenerate a slightly larger portion of the slide than Claude Code would. For presentation slides this is completely fine — just expect the preview to reload a bit more broadly.
3

Prepare your document as a brief

Extract and structure the content — 5–10 minutes, the most important step

Open Design does not read your original Word or PDF file directly. You need to give it the content as structured text. This takes about 5 minutes and is the single most important factor in output quality — vague input produces generic slides, specific input produces slides you can actually present.

Open Notepad or VS Code and create a new file named my-brief.txt in your Open Design folder. Fill it in using this template:

my-brief.txt — fill this in before Step 5
PRESENTATION TITLE: [Your exact title, e.g. "HIPTECH: A Unified Patient Record System for Vietnam"] COURSE / SUBJECT: [e.g. "Software Engineering Capstone — Ho Chi Minh City University of Technology"] AUDIENCE: [e.g. "25 classmates + Supervisor Prof. Nguyen Van An"] PRESENTATION DURATION: [e.g. "10 minutes presentation + 5 minutes Q&A"] SECTIONS AND CONTENT: Slide 1 — Title slide Title, your name, date, course name Slide 2 — Problem statement Healthcare data in Vietnam is fragmented across 1,200+ hospitals. Duplicate patient records cause ~40% of diagnostic errors. No unified national system exists. Slide 3 — Proposed solution HIPTECH: a cloud-based unified patient record platform. REST API connects existing hospital systems without replacing them. Patients control their own data via a mobile app. Slide 4 — System architecture 3-tier architecture: React frontend, Node.js microservices, PostgreSQL. Deployed on Kubernetes. 99.9% uptime SLA. Include a simple architecture diagram. Slide 5 — Implementation results 1.2 million patient records processed in pilot. Response time: p95 under 200ms. Duplicate records reduced by 40% in pilot hospitals. Slide 6 — Conclusion + future work Successfully demonstrated feasibility. Next: national rollout, mobile offline mode, AI diagnostic suggestions. KEY NUMBERS TO EMPHASIZE: 1.2M records, 40% reduction in duplicates, 200ms p95, 1,200+ hospitals TONE: Professional academic. Clear and data-driven. Not overly casual.
💡
Replace every [green placeholder] with your real content. The more real detail you add — actual numbers, actual section titles, actual findings from your document — the better the slides will be. You will paste this file's content directly into the prompt in Step 5.
4

Choose your skill and design system

Two dropdown controls that define the type of artifact and its visual language

Skill → select guizang-ppt

In the top bar, click the Skill dropdown. Select guizang-ppt — this is the default deck skill, based on the widely used guizang-ppt-skill. It produces a horizontal-swipe HTML deck with editorial magazine-quality layout, multiple theme options, and outputs a slides.json file for PPTX export.

💡
Why guizang-ppt? It has the deepest reference library of any OD deck skill — themes, layout catalog, a quality checklist — which means OpenCode has much more guidance to work with. The result is consistently better than simple-deck. The tradeoff is it takes slightly longer to generate (~2–3 minutes).

Design system → pick one for your presentation

Click the Design System dropdown. Here are the best choices for an academic or technical presentation:

💡
For a software engineering or healthcare IT project presented to a class and supervisor: Linear (if your supervisor is technical) or Neutral Modern (if you're unsure). Both look professional on a projector and read clearly from the back of a room.
5

Write and send your first prompt

This triggers the discovery form on Turn 1 — do not skip it

Click into the prompt box at the bottom of the chat pane. Paste the content from your my-brief.txt file, or use this structure directly. Adjust the placeholders to match your actual document:

Prompt to paste into the chat box — then hit Send
Create a presentation deck for my [course name] presentation for [supervisor name] and my class. Title: "[Your presentation title]" Sections to cover: 1. Title slide — [your name, date, course] 2. Problem — [1–2 sentences about the problem] 3. Solution — [1–2 sentences about your approach] 4. Architecture / Method — [brief description + key diagram if needed] 5. Results — [key numbers and outcomes] 6. Conclusion — [summary and future work] Key numbers to highlight: [list your most important metrics] Audience: [N] classmates + supervisor [name] Duration: [N] minutes Tone: Professional academic, clear and data-driven
⚠️
Before hitting Send — confirm the top bar shows: Agent = OpenCode, Skill = guizang-ppt, Design System = your chosen system. If any of these are wrong, fix them now. Once you send, generation starts with whatever is currently selected.

When everything is set, hit Send. The agent will respond within a few seconds — not with slides, but with a question form. This is correct and expected.

6

Answer the discovery form

Turn 1 — a 30-second brief that locks the design parameters before anything is built

The agent's first response is always a question form — not code, not slides. This is enforced by the discovery prompt rules and cannot be skipped. It exists to prevent the agent from improvising bad aesthetic decisions. Answer all questions:

Discovery form — answers for a class presentation
What are we making?
✅ Slide deck / pitch
Primary surface
✅ Fixed canvas (1920×1080) — standard projector ratio
Who is this for?
Type: Class of [N] + supervisor — academic presentation
Visual tone (up to 2)
✅ Modern minimal + Tech / dark UI for engineering
or Modern minimal + Editorial / magazine for research
Brand reference
Leave blank, or type: Academic — use the active design system

Click Submit. The agent moves to Turn 2.

7

Pick a visual direction

Turn 2 — choose one aesthetic from 5 curated options

The agent now shows a second form with 5 visual directions. Each is a complete aesthetic package — a specific OKLch color palette, font pairing, layout rhythm, and spacing posture. Pick the one that fits your audience and topic.

DirectionVisual characterWhen to pick it
Editorial / magazineSerif headlines, dramatic contrast, asymmetric layoutResearch with a strong narrative arc
Modern minimalClean sans-serif, generous whitespace, precise grid✅ Best for engineering / technical topics — universally readable
Tech / dark glassDark background, glowing accent color, monospace details✅ Software systems, architecture — visually striking
Warm / humanWarm palette, rounded forms, approachableHealthcare, user research, or social topics
Brutalist / rawBold type, raw layout, high-contrast bordersDesign or creative topics — not conservative audiences
💡
For a software engineering or healthcare IT project presented to a mixed academic audience: Modern minimal is the safest and strongest choice. It looks professional, projects clearly, and won't distract from your content. If your supervisor is deeply technical and you want more visual impact, Tech / dark glass is excellent.

Select your direction and click Submit. The agent now has everything it needs and will not ask any more questions. Generation begins immediately.

8

Watch the generation

Turn 3+ — OpenCode builds the deck live, takes 2–3 minutes

OpenCode now has the full context and starts building. Watch these things happen in real time:

0–10 seconds

TodoWrite plan streams in

A live list appears in the chat pane: "Read references/checklist.md", "Read references/layouts.md", "Plan 6 slides", "Write index.html", "Write slides.json". This is the skill's pre-flight step — OpenCode reads the skill's reference files before writing anything.

10–30 seconds

Skill references read

You'll see tool calls for reading references/themes.md, references/layouts.md, and references/checklist.md from the guizang-ppt skill. This is what makes the output follow the right layout patterns instead of improvising.

30–100 seconds

Files written to disk

The artifact tree on the right starts filling in: index.html (the deck), slides.json (slide data for export), assets/ (fonts, images). The preview iframe hot-reloads every ~100ms as files land — you'll see the deck taking shape.

100–140 seconds

Self-critique gate runs silently

OpenCode evaluates the deck against 5 dimensions: Philosophy, Hierarchy, Execution, Specificity, Restraint. If anything scores low it revises automatically before finishing. You don't need to do anything.

~2–3 minutes

Preview loads — deck is ready

The complete deck loads in the sandboxed preview iframe. Use arrow keys or scrollwheel to navigate between slides. Comment mode and the Export button are now active.

⚠️
Keep the PowerShell window open and do not close the browser tab during generation. If nothing happens for more than 3 minutes, the agent may have hit a context limit. Click Regenerate — the partial artifact is preserved and OpenCode will continue from where it left off.
9

Review and refine your deck

Use 3 refinement methods to improve the slides before exporting

Navigate through every slide in the preview. Check the content against your brief. Check that key numbers are visible and prominent. Check that the title slide has your name. Use one of three methods to fix anything that's off:

💬 Chat — structural changes

Type in the chat box for anything that involves layout, new sections, or multiple slides. E.g. "Add a slide between 3 and 4", "Merge slides 5 and 6", "Rewrite the conclusion".

🖱️ Comment mode — element edits

Click any element in the preview → popover appears → type your note. E.g. click a title → "Make this larger". Click bullet points → "Reduce to 3 items max". Faster than full chat regeneration.

🎛️ Sliders — aesthetic tweaks

If sliders appear in the sidebar (depends on skill version), drag them to adjust accent hue or spacing. Instant visual feedback with no prompt needed.

🔄 Regenerate — when off-target

If the whole deck misses the mark, click Regenerate. Refine your prompt first — be more specific about section content and key numbers. Previous artifact is always saved.

The most common refinements for academic presentations

Copy any of these into the chat box as needed
// Slides have too much text "Each slide has too much text. Reduce every slide to a maximum of 3 bullet points. Keep only the most important point per bullet." // Title slide is missing your details "Update the title slide: author is [Your Full Name], institution is [University Name], date is [Month Year], supervisor is [Name]." // A specific slide needs more detail "Expand slide 4 (System Architecture) to include a simple 3-layer diagram: Frontend → API Layer → Database." // Text too small for a projector "Increase the base body font size to at least 22px across all slides. Heading text should be at least 40px." // Conclusion is weak "Rewrite the conclusion slide. End with a clear summary of 3 key contributions, then 2 future directions, then a Thank You with my contact info." // Wrong number of slides "Reduce to exactly 8 slides. Merge slides 5 and 6. Keep the most important content from each."
💡
How many refinement rounds? For a class presentation, 1–2 chat refinements and 2–3 comment-mode tweaks is usually enough. Don't over-iterate — the self-critique gate already ran once and improved the output. Focus on: (1) correct content, (2) readable text size, (3) your name on the title slide.
10

Export your deck

Get the file format you need for presenting or submitting

Click the Export button in the top-right corner of the UI. Choose the format based on how you'll use the deck:

Best for live presenting
🌐

HTML (self-contained)

Opens in any browser. Arrow keys to navigate. Full animations. Works fully offline. No software installation needed on the presentation computer.

📄

PDF

For printing, emailing to your supervisor, or submitting alongside your report. Each slide becomes one page. Requires Phase 2 (Puppeteer). Use HTML if PDF isn't available yet.

📊

PPTX

For PowerPoint or sharing with people who expect a .pptx file. Generated from slides.json via pptxgenjs. Requires Phase 2. Some animations won't transfer.

Your files are already on disk

# Artifact is saved here (regardless of export):
D:\WorkSpace\HIPTECH\open_design\open-design\
  .od\artifacts\
  └── <timestamp>-<title-slug>\
      ├── index.html     ← double-click to present in browser
      ├── slides.json    ← source data for PPTX export
      └── assets\        ← fonts and images

How to present from the HTML file

  1. Double-click index.html in Windows Explorer — opens in your default browser
  2. Press F11 to enter full-screen mode
  3. Use ← → arrow keys or scrollwheel to move between slides
  4. Press Escape to exit full-screen
💡
Before the actual presentation: test the HTML file on the exact computer and projector you'll use. Open it in full-screen, navigate through every slide, and check that text is readable from the back of the room. If any text is too small, go back to Step 9 and increase font sizes — it takes 1 minute.

! Troubleshooting

Common issues and fixes

OpenCode not detected on daemon startup

# Verify opencode is on PATH
opencode --version

# If "not recognized", install it:
npm install -g @opencode-ai/opencode

# Restart the daemon (Ctrl+C in the daemon window, then run again):
corepack pnpm run dev:all

Generation stops mid-way or times out

Click Regenerate. The partial artifact is preserved. If it keeps failing, simplify your prompt: reduce to 6 slides explicitly, shorten section descriptions to one sentence each. OpenCode may be hitting a context window limit with very long prompts.

Slides contain placeholder or generic content

Your brief was too vague. Go back to Step 3 and add real section titles, real numbers from your research, and a real audience description. The agent uses your specific details to avoid falling back on generic filler content.

Text is too small on the projector screen

Send in chat: "Increase body text to at least 22px and all headings to at least 40px across all slides."

Comment mode click does not open a popover

OpenCode has constrained surgical edit support. If clicking elements doesn't trigger the popover, use the chat box instead — describe the change by slide number and element: "On slide 2, change the subtitle to say [your text]."

The deck doesn't use the design system colors I picked

The guizang-ppt skill has an internal theme system that partially overrides DESIGN.md. To enforce your system more strongly, add to your next message: "Use ONLY the colors and fonts from the active design system. Do not use any internal theme colors."

PDF or PPTX export button is grayed out

These are Phase 2 features not yet available in v0.3. Use the HTML export instead — it is actually better for live presenting. If you need a PDF for submission, open the HTML file in Chrome, press Ctrl+P, and print to PDF.

The daemon PowerShell window shows an error after a while

This usually means the agent hit a rate limit or the API key expired. Stop the daemon (Ctrl+C), verify your API key is still valid, and restart with corepack pnpm run dev:all. Your artifact is already saved on disk and won't be lost.
