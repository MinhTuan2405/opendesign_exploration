01 What is it?

Open Design in one sentence

Open Design (OD) is an open-source, local-first design studio that turns your existing coding agent — Claude Code, Codex, Cursor, Gemini CLI, OpenCode, Qwen — into a full-stack design engine driven by composable skills and brand-grade design systems.

The core idea: OD doesn't ship its own AI model. The strongest coding agents already live on your laptop. OD wires them into a skill-driven design workflow — adding structure, taste, and a deterministic output contract — so they produce design artifacts instead of generic code.

The result is a platform where typing "make me a magazine-style pitch deck for our seed round" produces a real, shippable HTML artifact with editorial-grade layout, a curated palette, live preview in a sandboxed iframe, and a self-critique gate — not a rough prototype that needs extensive cleanup.

02 Why it exists

The origin story

Anthropic released Claude Design on April 17, 2026 (with Opus 4.7), showing what happens when an LLM stops writing prose and starts shipping design artifacts. It went viral immediately — and stayed closed-source, paid-only, cloud-only, locked to Anthropic's model and skills.

There was no checkout, no self-host, no Vercel deploy, no swap-in-your-own-agent. Zero portability.

Open Design is the direct answer: same artifact-first mental model, same loop, none of the lock-in. Apache-2.0. Self-host anywhere. Use any agent. Bring your own key at every layer.

The thesis

The code agent space has already converged on a few strong implementations (Claude Code, Codex, Cursor Agent, Gemini CLI, OpenCode, Qwen). Reimplementing another one is worse than talking to all of them. OD's job is to detect the agent, feed it a skill + prompt + working directory, and stream its output back to the web UI.

03 Mental model

The composable stack

Every generation in Open Design is the product of three things composing together:

SKILL.md
The workflow — what to build, how to build it, what checklist to run, what reference files to read first. Defines the design surface (prototype, deck, dashboard, landing page).
+
DESIGN.md
The visual identity — 9-section brand document: palette in OKLch, font stack, spacing scale, component patterns, motion, voice. Defines the aesthetic language.
+
Agent CLI
The execution engine — your existing coding agent on $PATH. Receives the composed prompt, writes files to disk, streams output back to the preview iframe.
=
Artifact
A real shippable file — plain HTML/CSS/JS in ./.od/artifacts/<slug>/. Open in browser, commit to git, deploy to CDN, export as PDF or PPTX.

The pairing is what gives OD its power: saas-landing + Linear system produces a landing page in Linear's visual language. The same skill + Stripe system produces the same structure in Stripe's aesthetic. Swap one dimension, the other holds constant.

05 Open-source origins

Standing on open-source shoulders

Open Design is built on four open-source foundations, each contributing a distinct capability:

alchaincyf/huashu-design

The design-philosophy compass. Contributes: Junior-Designer workflow, 5-step brand-asset protocol, anti-AI-slop checklist, 5-dimensional self-critique, and the "5 schools × 20 design philosophies" idea behind the direction picker. Distilled into src/prompts/discovery.ts.

op7418/guizang-ppt-skill

The deck mode. Bundled verbatim under skills/guizang-ppt/ with original LICENSE preserved. Magazine-style layouts, WebGL hero, P0 self-check. The reference implementation for all deck skills.

multica-ai/multica

Agent detection pattern — PATH-scanning for multiple CLI tools and maintaining an adapter pool. The inspiration for OD's multi-agent adapter system.

OpenCoworkAI/open-codesign

The UX layer. Sandboxed iframe preview with vendored React 18 + Babel, the comment-mode interaction pattern, and the codesign methodology for human-agent collaboration.

06 Audience

Who is Open Design for?

🖥️ Developers who design

Already have Claude Code or Codex. Want design-quality output from their existing agent — no new tools, no new accounts. Just wire in the skill layer and get design artifacts instead of generic code.

✏️ Designers who code

Want to produce shippable HTML artifacts, not static Figma mockups. OD handles code quality; the designer guides the aesthetic via DESIGN.md, direction picker, and comment mode.

🏢 Teams needing consistency

Commit a DESIGN.md and shared skills/ folder to the repo. Every team member's generations follow the same brand system automatically. Review designs in pull requests.

🔓 Escaping vendor lock-in

Same artifact-first mental model as Claude Design, self-hosted. Swap models, self-host on Vercel, run fully local. Apache-2.0 — use commercially, fork freely.

07 Scope

What Open Design is NOT

✗
Not a design tool like Figma — artifacts are shippable HTML/CSS/JS files, not vector design files. There's no canvas, no component library, no inspection panel.
✗
Not a no-code website builder — you own the code and need to understand it. The output is code, not a drag-and-drop site.
✗
Not a hosted SaaS — it runs locally (Topology A) or self-hosted on Vercel (Topology B/C). No managed hosting, no usage metering.
✗
Not a replacement for taste — it amplifies taste. You still need to pick the right design system, write a good brief, and use comment mode to guide the refinement.
✗
Not a new AI model — it uses your existing agent. The intelligence is provided by Claude Code, Codex, or whichever agent you have installed.
