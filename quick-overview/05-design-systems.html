01 Concept

What is a design system in OD?

In Open Design, a design system is a portable DESIGN.md file following a 9-section schema. It encodes a brand's complete visual identity — palette, typography, spacing, components, motion, voice — in a format that can be injected into the agent's system prompt before every generation.

The design system is the answer to: "what should this look like?" The skill is the answer to: "how should we build it?" Together they produce a generation that is both correctly structured and visually coherent.

The pairing effect: dashboard skill + Linear system = a dashboard in Linear's visual language. The same skill + Stripe = the same structure in Stripe's design language. Swap one dimension; everything else holds constant.
02 Format

The 9-section DESIGN.md format

Every design system follows this 9-section schema (from the awesome-claude-design spec). Skills can request only specific sections via od.design_system.sections to save tokens.

#SectionKey contentsMost used by
1IdentityBrand name, tagline, positioning, voice personalityAll skills
2ColorPrimary, secondary, surface, semantic tokens in OKLch + hex; dark mode variantsAll skills
3TypographyFont stack, scale (rem), weight ramp, line-height, letter-spacing, heading rulesAll skills
4SpacingBase unit, spacing scale, layout grid, content max-width, column countPrototype, dashboard
5ComponentsButton variants, input styles, card patterns, badge, navigation, modal specsPrototype, dashboard
6IconographyIcon set name, style (outline/filled), sizing convention, common namesDashboard, docs
7ImageryPhotography style, illustration guidelines, usage rules, asset sourcesLanding page, deck
8MotionEasing curves (cubic-bezier), duration scale, interaction patterns, reduced-motion handlingPrototype
9Voice & ToneWriting style, formality level, tone guidelines, example copy, anti-patternsLanding page, blog

Example DESIGN.md structure

# Acme Corp Design System
## Brand: Acme Corp · "Move fast, stay beautiful"

## 1. Identity
Product: Developer infrastructure for API teams.
Voice: Direct, precise, never corporate. Write like a senior engineer who can also design.
Positioning: Fast, reliable, beautiful. In that order.

## 2. Color
Primary:   oklch(55% 0.22 250)  # #1a5fd4 — electric blue
Accent:    oklch(68% 0.20 30)   # #e8763c — warm orange
Surface:   oklch(98% 0.01 250)  # #f8f9fe — near-white
Text:      oklch(15% 0.02 250)  # #111827 — near-black
Danger:    oklch(55% 0.22 25)   # #d14040
Success:   oklch(50% 0.18 145)  # #2a7a3a

Dark mode:
Surface-dark: oklch(12% 0.02 250)
Text-dark:    oklch(90% 0.01 250)

## 3. Typography
Display: "Cal Sans" 700 · scale: 4rem / 3rem / 2rem
Heading: "Inter" 600
Body:    "Inter" 400 · 1rem / 1.75 line-height
Mono:    "JetBrains Mono" 400 · 0.875rem

## 4. Spacing
Base unit: 8px · Scale: 4/8/12/16/24/32/48/64/96/128px
Container max-width: 1200px · Content: 720px
Grid: 12 columns · Gap: 24px

## 5. Components
Button/primary: primary color · 36px tall · 12px radius · 500 weight · uppercase 12px
Button/ghost:   transparent · 1px border primary · same dims
Card:           white · 1px border #e5e7eb · 24px padding · 12px radius · no shadow
Input:          36px · 4px radius · 1px border #d1d5db · focus: 2px primary ring

## 6. Iconography
Library: Heroicons (outline variant only) · 20px default · 24px for navigation

## 7. Imagery
Photography: dark, moody, technical environments. No stock-photo smiles.
Illustrations: geometric, minimal, monochrome. SVG only.

## 8. Motion
Easing: cubic-bezier(0.4, 0, 0.2, 1) (material standard)
Duration: 150ms micro · 250ms standard · 400ms complex
Rule: animate transform and opacity only. No layout animations.

## 9. Voice
Do: "Start building in 5 minutes." "Zero config." "Works with your stack."
Don't: "Empower your team to leverage." "Best-in-class." "Industry-leading."
Headlines: Fragment sentences OK. Active verbs. Numbers when possible.
03 Resolver

How the design-system resolver works

The daemon's design-system resolver loads a DESIGN.md on boot and hot-reloads it in dev. It looks in these locations in order:

1st
Highest
./DESIGN.md — project root. This is where you put your brand system. Overrides everything.
2nd
./design-system/DESIGN.md — project subdirectory. Alternative location if you prefer a dedicated folder.
3rd
User-configured path in ./.od/config.json — point to any absolute path on disk.
Fallback
72 built-in systems from the dropdown. Selected via the Design System picker in the top bar. These are read-only and live in the OD install directory.

The resolver parses the 9-section format once, caches the body in memory per session, and injects it as a prepended system message on every agent run. It also makes the body available as a {{ design_system }} template variable that skills can reference.

04 Injection

Injection and token pruning

The full DESIGN.md is injected before every generation. For large brand documents, this can add significant tokens. Skills can prune the injection to only what they actually need:

# In your SKILL.md frontmatter:
od:
  design_system:
    requires: true
    sections: [color, typography]  # Only inject sections 2 and 3

Which sections each skill type typically needs

Skill typeSections needed
Deck / presentationcolor, typography (sections 2, 3)
Marketing landing pagecolor, typography, spacing, components, imagery, voice (2,3,4,5,7,9)
Dashboard / app UIcolor, typography, spacing, components, iconography, motion (2,3,4,5,6,8)
Blog / editorialcolor, typography, imagery, voice (2,3,7,9)
Documentationcolor, typography, components, iconography (2,3,5,6)

06 Writing a system

Building a brand design system

Create ./DESIGN.md in your project root. The daemon finds it automatically. Use the template below as a starting point:

# [Brand Name] Design System
## [Tagline]

## 1. Identity
Product: [What it does in one sentence]
Voice: [Describe tone: technical/warm/playful/authoritative]
Positioning: [Key differentiators]

## 2. Color
# Use OKLch for perceptual uniformity + hex fallback
Primary:   oklch(L% C H)  # #hexvalue — description
Accent:    oklch(L% C H)  # #hexvalue — description
Surface:   oklch(L% C H)
Text:      oklch(L% C H)
Danger:    oklch(L% C H)
Success:   oklch(L% C H)

## 3. Typography
Heading: "[Font family]" [weight] · scale: [rem values]
Body:    "[Font family]" [weight] · [size]rem / [line-height]
Mono:    "[Font family]" [weight]

## 4. Spacing
Base unit: [N]px · Scale: [list values]
Container: [N]px max-width · Content: [N]px

## 5. Components
Button: [height] · [radius] · [weight] · [style notes]
Card: [padding] · [border] · [radius]
Input: [height] · [radius] · [border] · [focus style]

## 6–9. [Fill in iconography, imagery, motion, voice as needed]

OKLch color — why and how

OKLch (Lightness, Chroma, Hue) produces perceptually uniform colors — equal lightness steps look equal to the human eye, unlike hex values. Formula: oklch(L% C H) where L is 0–100 (lightness), C is 0–0.4 (chroma/saturation), and H is 0–360 (hue angle).

Blue primary (rich)

oklch(55% 0.22 250)
L=55 (medium dark), C=0.22 (saturated), H=250 (blue-purple)

Accent orange (warm)

oklch(68% 0.20 30)
L=68 (medium), C=0.20 (moderately saturated), H=30 (orange)

Surface (near-white)

oklch(98% 0.01 250)
L=98 (very light), C=0.01 (nearly gray), H=250 (slight blue cast)

Text (near-black)

oklch(15% 0.02 250)
L=15 (very dark), C=0.02 (nearly neutral), H=250 (slight cool cast)

07 From URL/screenshot

Generating a system from a reference

The design-system-gen skill (Design System mode) can extract a DESIGN.md from:

  • Text brief: "A B2B SaaS brand inspired by Linear: minimal, dark, precise. Primary blue, mono font for code."
  • Reference URL: Paste a URL; the agent fetches and analyzes the site's visual language (Phase 2)
  • Screenshot: Upload a screenshot; vision model extracts palette and typography (Phase 2)

After generation, OD prompts you to set the resulting DESIGN.md as the project's active system. From that point, every prototype, deck, and template generation uses your brand's exact visual language.

Recommended workflow for new projects: Run Design System mode first with your brand brief → set the result as active → then use Prototype or Deck mode. This is the single highest-leverage action for output quality and cross-artifact consistency.
